# Matched capability-chain analysis — v1.7

## Purpose
Test the same broad capability families across progressively wider system boundaries rather than comparing unrelated benchmark scores. These are matched families, not literal longitudinal experiments; match strength is coded explicitly.

## Capability families

1. **Practical biology assistance / novice uplift** — LAB-Bench → LABBench2 → BixBench → physical novice RCT. Apparent capability attenuates as tasks become more realistic and physical.
2. **Protein-design orchestration → functional binders** — BioDesignBench → Claude/Adaptyv wet-lab binder validation. Physical testing strengthens the bounded capability claim.
3. **Protein redesign for screening evasion** — in-silico concern → NIST physical TEVV with safe proxies. Physical testing attenuates the stronger security inference because predicted structural similarity did not reliably preserve activity while evading screening.
4. **AI-guided experimental execution / closed-loop optimization** — ABC-Bench → CRISPR-GPT → OpenAI/Red Queen. Capability strengthens as executable tools, physical action and interpretable feedback close the loop.
5. **Autonomous scientific research** — PaperBench/BixBench → Co-Scientist → physical X-ray scientist comparator. Composition can either block or enable capability depending on task structure, tools, expert oversight and feedback.
6. **Safety control quality** — RefusalBench → BioSecBench-Refusal. Overall refusal is reframed as a configuration-dependent proxy rather than direct evidence of calibrated hazard discrimination.

## Main result
**Boundary expansion has no single direction.** In some chains it reduces apparent capability or risk; in others it confirms or creates capability; in others it changes what the metric means. The system boundary is therefore an empirical variable, not merely a reporting choice.

## Cross-chain relational mediators
Repeated mediators include context, tool access, execution semantics, human expertise, authority to act, physical biological constraints, feedback interpretability and update capacity.

## Provisional synthesis
> Capability is not simply a property of the model. It is a property of the configured system. Security may be as well.

A more careful security claim should identify the boundary at which the evidence was generated and which causal arrows remain inferred between proxy, capability, workflow behavior, physical execution and consequential outcome.
